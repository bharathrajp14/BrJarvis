# Findings Draft

| ID | Severity | Area | Evidence | Impact | Recommended change |
|---|---|---|---|---|---|
| SEC-001 | High | Browser authentication | `src/brjarvis/web/api/routes/auth.py:26-89` stores sessions and WebSocket tickets in process-global dictionaries. There is no durable revocation/logout path, no per-client login throttling, and sessions disappear or diverge across worker processes. | Session behavior is inconsistent in multi-worker deployments; stolen session tokens remain valid until TTL; brute-force attempts are not throttled. | Introduce a session abstraction with durable or explicitly single-process semantics, token revocation/logout, bounded cleanup, and rate limiting keyed by client/IP plus safe deployment documentation. |
| SEC-002 | Medium | Cookie security | `auth.py:172-179` and `207-222` derive `secure` from `JARVIS_COOKIE_SECURE` defaulting to false and do not set an explicit cookie `path`. | A misconfigured deployment can transmit session cookies over cleartext HTTP; cookie scope is broader than necessary. | Default secure in production, set `path='/'`, preserve local HTTP override only when explicitly configured, and add tests. |
| SEC-003 | Medium | CSP/CORS | `src/brjarvis/web/api/server.py:178-185` allows `unsafe-inline`, `unsafe-eval`, multiple CDNs, `ws:`, `http:`, and `https:`; `211-217` allows credentials with all methods/headers. | XSS impact and cross-origin request surface are larger than necessary; security policy is difficult to reason about. | Derive CSP from actual assets and environment, remove unsafe directives where feasible, restrict methods/headers/origins, and test the rebuilt and legacy clients separately. |
| SEC-004 | Medium | Error information | `src/brjarvis/tools/runtime.py:330-339` returns `str(exc)` as `message` and `stderr` in canonical tool results. | Internal paths, provider errors, or sensitive operational details may reach model/user-facing responses. | Keep detailed exception data in structured logs/ledger, return stable safe error codes/messages to the agent, and redact sensitive values. |
| REL-001 | Medium | Lifecycle ownership | `bootstrap.py:75-85` registers an orchestrator shutdown hook while `server.py:161-166` directly shuts down the same orchestrator. | Shutdown can run twice and may close resources in an unexpected order; repeated startup/test isolation is fragile. | Make shutdown idempotent and choose one lifecycle owner, with explicit ownership tests. |
| REL-002 | Medium | Runtime reset | `bootstrap.py:103-107` resets only `_runtime_instance`; event bus, core runtime, tool runtime, queues, and session stores remain global. | Tests or embedded surfaces can inherit state across runs and may publish into stale resources. | Add coordinated reset hooks for test/dev use and document production singleton lifecycle. |
| DATA-001 | High | Task state concurrency | `task_state.py:312-351` performs read-modify-write of an entire JSON snapshot with no compare-and-swap/version predicate; `record_action` also reads then saves. | Concurrent workers can lose task actions/status/checkpoints; last writer wins silently, compromising durable execution evidence. | Add optimistic versioning or transactional mutation APIs, atomic transition validation, and concurrency regression tests. |
| DATA-002 | Medium | Database schema | `canonical_db.py` uses many JSON snapshot columns and `INSERT OR REPLACE` for task rows; replace semantics can delete/reinsert rows and undermine foreign-key identity if referenced. | Persistence is difficult to query/validate and concurrent writes are harder to reconcile; replace behavior can be unsafe around references. | Prefer `ON CONFLICT DO UPDATE`, explicit schema versioning/migrations, and normalized append-only task/event tables for critical evidence. |
| PERF-001 | High | Frontend snapshot | `frontend/src/platform/api-client.ts:101-110` performs nine concurrent API calls, then `148-152` performs up to 20 additional project-detail requests. | Initial control-plane load scales with project count and creates avoidable latency/request pressure. | Add a summary endpoint or include files in the projects response, cap/virtualize detail loading, cache stable data, and expose per-panel failure state. |
| UX-001 | Medium | Boolean normalization | `api-client.ts:67` uses `Boolean(raw.requires_approval ?? raw.requiresApproval)`, so the string `"false"` is treated as true. | Tasks can incorrectly display approval requirements and block or confuse users. | Add strict boolean normalization for string/number payloads and contract tests. |
| PERF-002 | Medium | WebSocket logging | `server.py:125-129` creates a new asyncio task per socket for every log line and does not enforce a bounded per-client queue. | High-volume logs can create unbounded pending work and message loss under slow clients. | Use per-client bounded queues with drop/coalesce policy and one sender task per connection. |
| ARCH-001 | Medium | Registry duplication | `tools/registry.py` maintains legacy `TOOL_REGISTRY`/`TOOL_SCHEMAS` and separately registers into canonical `ToolRuntime`; import-time lazy/core plugin registration is spread across this large module. | Tool definitions can drift, load-order bugs are difficult to diagnose, and the registry is a high-coupling composition point. | Make canonical `ToolRuntime` authoritative, retain a compatibility adapter temporarily, and add duplicate/schema consistency checks. |
| ARCH-002 | Medium | Orchestrator complexity | `orchestrator/core.py` owns memory recall, prompt construction, skill matching, deterministic actions, history, session state, provider loop, tool parsing, and evidence synthesis. | Changes to one concern risk regressions in others; testing requires large integration contexts. | Extract explicit context, command routing, conversation persistence, and execution-loop services behind stable interfaces. |
| UX-002 | Medium | Partial failure semantics | `api-client.ts:100-136` uses `Promise.allSettled` but converts most rejected panels into empty arrays and returns an apparently connected snapshot if any one request succeeds. | Users cannot distinguish empty data from failed data, and operational problems are hidden. | Carry panel-level loading/error metadata into the snapshot/store and render explicit degraded states. |
| SEC-005 | Low/Medium | Tool injection fail-open | `runtime.py:191-209` catches all prompt-injection inspection errors and continues. | A failing guard silently removes a defense layer. | Log at warning with a safe degraded-policy decision; fail closed for high-risk tools and test guard-unavailable behavior. |

## Confirmed baseline

- Python compilation passed.
- Full baseline pytest: `357 passed, 1 skipped in 54.08s`.
- Ruff/pyright/bandit wrapper results are inconclusive because the remote command wrapper stalled/failed to produce status artifacts; rerun using bounded direct commands or inspect executable availability before claiming results.

## Implemented in this pass

- **SEC-001 partial / session handling:** session, ticket, and handoff store mutations are now serialized; browser sessions can be revoked via `POST /api/auth/logout`; login failures are throttled per client for a bounded window; cookies have explicit `Path=/` and an environment-aware secure default.
- **SEC-004:** synchronous handler exceptions are logged with traceback server-side but returned to the agent/UI as a stable generic failure message rather than raw exception text.
- **UX-001:** frontend payload normalization now treats string values such as `"false"`, `"0"`, and `"off"` as false for approval, connector, and contact flags.
- Added focused regression coverage in `tests/unit/test_auth_security.py`; targeted tests pass.

## Scope limitations

This draft is not the final report. It contains only findings verified from the files read so far. The remaining route modules, connector boundaries, migrations, platform-specific code, frontend screens/styles, and deployment configuration require inspection before final severity or implementation scope is fixed.
